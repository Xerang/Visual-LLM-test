## 작업 기록

### 1. CI (2026-10-12)
- 무엇: `.github/workflows/ci.yml`. PR과 main 푸시마다 backend `mvn test`(PostgreSQL 16 서비스), vision `unittest`, frontend `npm ci && npm run build`.
- 정정(같은 날): 처음 올린 버전은 **실행되지 않았다.** 프로젝트가 저장소 최상위가 아니라 `bozor-photo-scan-gemini-updated/` 폴더 안에 있었는데, GitHub는 최상위의 `.github/workflows`만 읽기 때문이다(PR 템플릿·README 표시도 같은 이유로 안 됐다). 프로젝트 전체를 `git mv`로 저장소 최상위로 옮겨 고쳤다(경로 외 변경 없음, 이동 후 백엔드 44·AI 서버 16 테스트와 프런트 빌드 통과).
- 검증: 최상위 이동 후 PR #2에서 GitHub Actions 실행 결과로 확인한다.

### 2. 모델 비교 도구 (2026-10-12)
- 무엇: `vision/tools/evaluate.py`. 정답셋(사진별 정답 소분류 코드)으로 모델별 정밀도·재현율·완전 일치(소분류·대분류)와 응답 시간 중앙값을 계산한다.
- 정확성: `/v1/scan`과 같은 함수(`scan_images`)를 쓰도록 AI 서버 코드를 분리했다(동작 변화 없음, 기존 테스트 통과). 채점은 카테고리 다중집합 일치로 정의하고, 손으로 계산한 값과 비교하는 테스트를 넣었다.
- 무료 한도 보호: 성공 결과 캐시, 429 즉시 중단·이어 하기, `--max-calls`·`--sleep`.
- 검증: 테스트 9개 추가(AI 서버 테스트 16개 통과). 실제 Gemini로 1장 평가(머그잔·사과 → 정답 2개 모두 일치, 44.4초).
- 한계: 상품명·설명의 질과 캡션 가격 추출은 채점하지 않는다. 서비스는 Java에서 한 번 줄인 사진을 다시 정규화하지만, 도구는 Python 정규화만 한다(둘 다 긴 변 2048px JPEG).

### 버그 수정: Gemini 과부하가 "바로 실패"로 처리되던 문제 (2026-10-12)
- 발견: 위 실제 평가에서 Gemini가 `503 high demand`를 반환했다. AI 서버가 이를 502로 바꿔 Spring 워커가 **재시도 없이 실패** 처리하는 구조였다. 서비스였다면 Gemini가 잠깐 바쁘기만 해도 판매자가 "분석 실패"를 봤다.
- 수정: Gemini 500·503 → AI 서버 503 → Spring `AI_UNAVAILABLE`(재시도). 400·401·403·404·형식 오류는 그대로 502(바로 실패).
- 검증: AI 서버 테스트 2개, Spring `HttpVisionClientTest` 8개(상태 → 오류 코드·재시도 여부 전체 표) 추가. API 명세 5.5·7장 갱신.

### 3. 사진 접근 제어 (2026-10-12)
- 근거: 임시 결정 #9("검수 전 사진은 주인만, 공개 상품 사진만 공개"). 사진 id가 1, 2, 3… 순번이라 주소의 숫자만 바꾸면 다른 판매자가 아직 공개하지 않은 스캔 사진·초안 사진을 볼 수 있었다.
- 무엇:
  - 공개 사진 = 판매 중(`PUBLISHED`) 상품이 공개(`ACTIVE`) 상점에 있거나 공개 상점의 로고·배너. 서명 없는 주소로 누구나 본다(구매자 화면은 변경 없음).
  - 그 밖의 사진은 주인에게 준 응답(업로드 결과, 판매자 상품·스캔 작업·상점 응답)에 담긴 **서명 주소**로만 본다. 맞지 않으면 404.
  - 서명 = HMAC-SHA256(`"image:{id}:{exp}"`), 만료는 1시간 단위로 맞춤(폴링 중 주소가 안 바뀌어 캐시 유지). 서명 키는 JWT 키를 함께 쓰지만, JWT 서명 입력(base64url 문자열)에는 `:`가 없어 두 서명이 서로 바꿔 쓰일 수 없다.
- 왜 토큰 검사가 아닌 서명 주소인가: 화면의 `<img>`는 로그인 토큰 헤더를 보낼 수 없다. 쿠키 로그인으로 바꾸는 것은 임시 결정 #1(로그인 방식)과 엮여 있어 손대지 않았다. S3로 바꿀 때(#6)도 같은 서명 URL 방식이라 화면은 그대로다.
- 검증: `ImageAccessTest` 4개(업로드 사진은 서명 주소만 200·일반 주소 404 / 다른 사진에 서명 재사용·서명 변조·만료 연장 404 / 초안 404 → 판매 중 200(public 캐시) → 숨김 404, 판매자 서명 주소는 200 / 공개 상점 로고 200 → 상점 숨김 후 404), `ImageUrlSignerTest` 3개(만료 정렬, 만료 경계, 다른 키·다른 사진). 백엔드 전체 51개 통과. 브라우저(모바일 폭)에서 판매자 상품·AI 스캔 탭은 서명 주소, 공개 상점은 일반 주소로 사진이 깨짐 없이 표시됨.
- 한계: 로그아웃해도 이미 받은 서명 주소는 최대 2시간 유효하다. 상품을 숨기기 전에 받아 간 공개 사진은 브라우저·중간 캐시에 최대 하루 남을 수 있다. 장바구니에 담아 둔 상품이 숨겨지면 장바구니 썸네일이 안 보인다(그 상품은 주문도 막히므로 영향 작음).
